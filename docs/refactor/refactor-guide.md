# Next.js Finance App Refactoring Guide

## Project Context
This is a Next.js finance management application that was initially generated by AI. The codebase has accumulated unused code, duplicate functionality, and potential optimization opportunities that need to be addressed.

## Current Project Structure
```
finance-web/
├── app/ (Next.js 13+ App Router)
├── src/
│   ├── components/
│   ├── context/
│   ├── hooks/
│   ├── services/
│   ├── utils/
│   ├── views/
│   └── types/
├── docs/
└── public/
```

## Refactoring Objectives

### Phase 1: Analysis & Discovery
**Goal:** Identify all unused code, duplicate functionality, and optimization opportunities.

#### Tasks:
1. **Scan for unused imports and exports**
   - Check all files in `/src/components/`, `/src/hooks/`, `/src/utils/`, `/src/services/`
   - Identify components, functions, and utilities that are imported but never used
   - List all exports that have no import references across the codebase

2. **Identify duplicate functionality**
   - Look for similar components with overlapping purposes (e.g., multiple modal components, multiple list components)
   - Find duplicate utility functions (date formatting, API calls, validation)
   - Identify redundant context providers or hooks

3. **Analyze component structure**
   - List components in both `/app/components/` and `/src/components/` - determine if there's unnecessary duplication
   - Identify overly complex components that should be split
   - Find components that are too small and could be consolidated

4. **Review service layer**
   - Check for unused API endpoints in service files
   - Identify redundant API call patterns
   - Look for opportunities to consolidate similar service methods

5. **Examine error boundaries**
   - Count error boundary implementations: `ErrorBoundary.tsx`, `FeatureErrorBoundary.tsx`, `AsyncErrorBoundary.tsx`
   - Determine if all three are needed or if they can be consolidated

### Phase 3: Refactoring Execution
**Goal:** Clean up the codebase based on the analysis.

#### Instructions for AI:
1. **Start with high-confidence deletions**
   - Remove clearly unused components, utilities, and hooks
   - Delete commented-out code
   - Remove unnecessary console.logs and debug statements

2. **Consolidate duplicate code**
   - Merge similar components into reusable abstractions
   - Consolidate duplicate utility functions
   - Unify error boundary implementations if redundant

3. **Reorganize file structure**
   - Move misplaced files to appropriate directories
   - Ensure consistent directory structure
   - Update all import statements accordingly

4. **Optimize component patterns**
   - Apply consistent patterns across similar components
   - Extract common logic into custom hooks
   - Implement proper memoization where needed

5. **Clean up dependencies**
   - Remove unused npm packages from package.json
   - Update import statements to use consistent paths
   - Ensure all TypeScript types are properly defined

6. **Update documentation**
   - Update README.md to reflect new structure
   - Remove outdated documentation in /docs/plan/done/
   - Update component documentation

## Specific Areas to Review

### Components Directory Analysis
- Review `/src/components/` vs `/app/components/` - are both needed?
- Check if `LazyRoute.tsx` and `ProtectedShell.tsx` in `/app/components/` have equivalents in `/src/components/`

### Error Boundary Consolidation
Analyze these three error boundaries:
- `/src/components/ErrorBoundary.tsx`
- `/src/components/FeatureErrorBoundary.tsx`
- `/src/components/AsyncErrorBoundary.tsx`

Determine: Can they be consolidated into one flexible component with props?

### Transaction Components
Review the transaction list implementations:
- `/src/components/TransactionList/`
- `/src/views/Transactions/components/TransactionList/`

Are both needed? Can they be consolidated?

### Context Providers
Review contexts in `/src/context/`:
- `AuthContext.tsx` vs `AuthStateContext.tsx` - are both necessary?
- Check for any unused context providers

### Service Layer
Review `/src/services/`:
- Identify unused service methods
- Look for opportunities to consolidate API calls
- Check if `index.tsx` in services is being used correctly

### Utility Functions
Review `/src/utils/`:
- Check usage of each utility file
- Identify any duplicate functionality
- Consolidate similar utilities

## Constraints & Guidelines

### DO NOT Delete:
- Any code that's part of active features visible in the UI
- Configuration files (next.config.js, tsconfig.json, etc.)
- Documentation that describes current architecture
- Service worker and PWA-related files

### DO Delete:
- Clearly unused components with zero imports
- Commented-out code blocks
- Debug console.logs in production code
- Unused utility functions
- Duplicate implementations of the same functionality

### Code Quality Standards:
- Maintain TypeScript strict mode compliance
- Keep consistent naming conventions
- Ensure all components have proper prop types
- Follow Next.js 13+ App Router best practices
- Maintain accessibility standards

## Testing After Refactoring

After completing refactoring, verify:
1. All pages still load correctly
2. No TypeScript errors
3. No broken imports
4. All features function as expected
5. Bundle size has decreased
6. No console errors in browser
